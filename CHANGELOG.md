# Changelog

## [0.7.0] - Unreleased

Focus release: correct checks, a working GitHub Action, a 4-package install and docs that match the code. It also fixes a High-severity issue in `kovar record` (see Security).

### Breaking changes

- **Checks that could not run now fail instead of passing.** Network-backed checks report a **high** finding when they could not verify anything: `auth-check-error`, `cors-check-error`, `csrf-check-error`, `csrf-check-unauthenticated`, `xss-check-error`, `xss-no-forms`, `headers-check-skipped`, `audit-page-closed`. These are never written to a CI baseline.
- **CSRF needs a logged-in request context.** An anonymous `request` now reports `csrf-check-unauthenticated` instead of passing.
- **Misspelled names throw.** Unknown names in `audit({ checks })` and in header `skip`/`only` throw, listing the valid names.
- **Removed options throw:** `allowXFrameOptionsSameOrigin` (headers), `expectedStatus` (auth) and `tokenCookies` (CSRF). None of them ever had an effect.
- **Compliance mapping removed.** `evaluateASVS`, `evaluatePCIDSS` and `formatComplianceReport` are no longer exported, and the compliance docs are gone. 6 of 14 ASVS 4.0.3 IDs were mapped to the wrong requirement, and the PCI-DSS numbering was unverified. A wrong compliance claim is worse than none.
- **Auth check uses an isolated request context.** `toRequireAuthentication`, `checkAuth` and `security.auth` no longer send the caller's cookies, `storageState`, `extraHTTPHeaders`, HTTP credentials or client certificates. Relative URLs resolve against the project's `baseURL` or the new `baseURL` option.
- **`kovar record --heal` requires confirmation.** It asks before every run of generated code, and needs `--yes` when stdin is not a terminal. The `--heal` child gets an allowlisted environment (`PATH`/`HOME`-style variables, proxy settings, `BASE_URL`, `TEST_*`, plus names in `KOVAR_HEAL_ENV`).
- **Recorder:** generated tests may only read `process.env.BASE_URL` and `process.env.TEST_*`; `.env.example` names are now `TEST_*`. The OpenAI provider has no default model, so pass `--model`. When AI generation fails, the fallback is written as `<name>.recording.json` (was `<name>.recording.spec.ts`).
- **CLI `.env` loading** is limited to `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `BASE_URL` and `TEST_*`, and only for `kovar record`.
- `@modelcontextprotocol/sdk`, `better-sqlite3` and `@babel/*` are optional peer dependencies. Install them to use the MCP server or the Babel/Vite/Next plugins.
- `engines.node` is `>=20.19.0` (was `>=18`).

### Security

- **`kovar record` prompt injection could exfiltrate environment secrets (High, CVSS 3.1 8.0, affects 0.2.0–0.6.0).** Page content was trusted input to LLM test generation, so a malicious page or a third-party iframe could forge accepted assertions or inject prompt text. The generated test would then read environment variables and send them to an attacker's URL. With `--heal` the code ran immediately with the full parent environment. Fixes:
  - page-originated assertions are no longer trusted;
  - prompt inputs are fenced and sanitized;
  - generated-code validation is stricter (still defense in depth, not a sandbox);
  - `--heal` requires confirmation and runs with a minimal environment;
  - `--source` lookups are confined to the source directory;
  - redaction gaps are closed before data is sent to the LLM.

  If you committed tests generated by `kovar record`, review them for `process.env` reads and outbound URLs.
- CLI: an untrusted `./.env` could set `NODE_OPTIONS`, `PATH` or `KOVAR_DB_PATH` for every command. It is now allowlisted (see Breaking changes).
- GitHub Action PR comment: strings from the scanned site are escaped.
- MCP: `runs.db` is created owner-only (dir `0700`, files `0600`), and `assert_messages_match` regex evaluation is bounded to 1 s.
- Release pipeline:
  - workflow tokens are least-privilege;
  - every action is pinned by commit SHA;
  - the publish job runs no install scripts;
  - prereleases publish to the `next` dist-tag;
  - a release tag must match `package.json`.
- The recorder no longer evades bot detection (no `AutomationControlled` flag, user-agent rewrite or `navigator.webdriver` override).

### Fixed

- **Detection accuracy.** Against a 45-case known-good / known-vulnerable fixture, 0.6.0 was wrong on 33 cases. On the 57-case suite that now runs in CI, 52 pass and 5 are known gaps kept visible as `test.fail` (DOM/SPA, stored and filter-bypass XSS). Main fixes:
  - **Auth:** stopped following redirects, so redirect-to-login is no longer "unprotected". Unreachable endpoints are reported. An auth-setup project's `storageState` no longer makes protected endpoints look unprotected.
  - **XSS:** submits hidden fields, so CSRF-token forms (Rails/Django/Laravel) are tested. Inspects 4xx responses. Uses context-aware reflection to remove false positives. Fixed DOM mode (typeless buttons, `goBack` hang).
  - **CSRF:** probes like a cross-site form (form-encoded, `Origin` set, no redirect following), so JSON-only and Origin/Fetch-Metadata defenses are no longer flagged. Sends a control GET to tell "not logged in" apart from a defense.
  - **CORS:** probes bypass origins derived from the host (`includes`/`startsWith`/`endsWith`) and actual requests, not only preflight. Reads `trustedOrigins`. Reports network errors.
  - **Headers:** parses CSP per directive (`default-src` fallback, scheme sources, case-insensitive, `'strict-dynamic'`). Handles repeated headers, `frame-ancestors` superseding XFO, and quoted HSTS `max-age`. Adds a hint for HSTS over plain http.
  - **Cookies:** fixed session-name heuristics (`_app_session`, `laravel_session`, `appSession`, `vercel_session_id`). `XSRF-TOKEN`/`csrftoken` are no longer treated as session cookies. Fixed the `__Host-` domain check.
  - **Fixture:** XSS, headers and CSRF run with the page's cookies (`page.context().request`), so headers are checked on the page you are on, not on a login redirect. `audit()` returns `checksRun`. A closed page is reported instead of passing. `SecurityAssertionError` includes `Fix:` lines.
- GitHub Action (`.github/actions/security-check`) now works. It is a composite action that installs `@orlalabs/kovar` and `@playwright/test`, installs Chromium and runs the newly built and shipped `dist/ci/index.js`. Previously the entry was never built or published, crashed on `require` inside ESM, and depended on `playwright-core` without declaring it.
- With a baseline, the action now fails only on **new** findings; previously `passed` ignored the baseline, so known findings blocked every PR. Findings that report a check could not run (`*-check-error`, `*-check-skipped`, `xss-no-forms`, `csrf-check-unauthenticated`, `audit-page-closed`) always block and are never written to a baseline.
- The action validates `fail-on` (case-insensitive). Previously any value other than an exact lowercase severity (for example `High`) made the gate compare against `undefined`, so nothing ever blocked and the job passed.
- The action rejects unsupported `checks` values (for example `xss`) instead of silently skipping them and reporting a pass.
- `@orlalabs/kovar/vite`, `/babel` and `/next` no longer fail with `ERR_MODULE_NOT_FOUND` for `@babel/*` from a clean install: the Babel packages are declared as optional peer dependencies (Babel 7 or 8).
- `tsup` clean race that randomly dropped plugin `.d.ts` files.

### Added

- Action writes `kovar-report.json` (findings, gate result, baseline status, framework-specific remediation) and `kovar.sarif` (SARIF 2.1.0) to `output-dir`, exposes `json-path`, `sarif-path` and `blocking-count` outputs, writes the job summary, and updates a single PR comment instead of posting a new one per run.
- `@orlalabs/kovar/ci/baseline` subpath export (was documented but not exported). `detectFramework` exported from `@orlalabs/kovar/core` (was documented but not exported).
- `npm run test:accuracy`: the detection-accuracy suite (fixture app plus real browser), run in CI.
- `toRequireAuthentication` / `checkAuth` option `baseURL`.
- `kovar record --yes` / `-y`.

### Changed

- `@modelcontextprotocol/sdk` and `better-sqlite3` moved from `dependencies` to optional `peerDependencies`. Installing Kovar for its assertions now adds 4 packages instead of 134, with no native build. To use `kovar mcp`, `kovar mcp proxy`, `kovar ingest` or `@orlalabs/kovar/mcp`, run `npm install -D @modelcontextprotocol/sdk better-sqlite3`.
- `engines.node` raised from `>=18` to `>=20.19.0` (Playwright 1.65 requires Node 20+, and `better-sqlite3` 12 already refused Node 18). Build target raised to `node20`.
- CI tests Node 20, 22 and 24 and Playwright from the supported floor through the latest release, and smoke-tests the packed tarball.
- Default Anthropic model for `kovar record` is `claude-sonnet-5-5` (was `claude-sonnet-4-20250514`).
- The XSS check is documented as what it is: it detects server-side reflected XSS in HTML forms, not DOM/SPA, stored or filter-bypass XSS.
- Docs rewritten to match the code: a runnable quickstart (`baseURL`, `playwright install`), local-http guidance, accurate option tables and cookie patterns, and could-not-run findings.

### Deprecated

These print a `DeprecationWarning` on stderr and will be removed in 0.8:
- **MCP server** (`kovar mcp`, `kovar mcp proxy`, `kovar ingest`, `@orlalabs/kovar/mcp`). It is moving to Orla Labs Caliper.
- **Recorder** (`kovar record`, `--heal`). It gets security fixes only until removal.
- **Accessibility check** (`toBeAccessible`, `security.accessibility`, `checkAccessibility`). Use `@axe-core/playwright` instead.

### Removed

- Compliance mapping (OWASP ASVS / PCI-DSS) and its docs.
- Options `allowXFrameOptionsSameOrigin`, `expectedStatus`, `tokenCookies`.

## [0.2.0] - 2026-03-22

### Added

#### AI-Powered Recorder
- AI-powered browser recording: `kovar record <url>`
- Page Object Model code generation (separate .page.ts + .spec.ts files)
- CLI with Anthropic and OpenAI LLM support (raw fetch, zero SDK dependencies)
- Action capture via browser-side injection (click, input, change, submit, keypress)
- SPA navigation monitoring (pushState, replaceState, popstate)
- Network capture (fetch/xhr with 10KB body limit, 500 request cap)
- Shadow DOM toolbar overlay with live counters, pause/resume, stop
- Locator generation with priority cascade (role > text > testid > placeholder > id > css)
- Auto-generated ID detection (React, Ember, Next.js, Radix, UUID patterns)
- Watchdog timer (5min idle timeout + 30min max recording duration, configurable)
- Graceful Ctrl+C handling (SIGINT closes browser cleanly)
- LLM fetch timeout (60s AbortController on both providers)
- LLM response validation (structure checks before accessing nested fields)
- .env file auto-loading in CLI
- .env.example generation with detected credential variables (BASE_URL, TEST_EMAIL, TEST_PASSWORD)
- PII masking in form values (password, email, phone, SSN/CPF/CNPJ/card patterns)

#### Codebase Awareness
- Codebase awareness: Vite plugin (`kovar/vite`), Next.js wrapper (`kovar/next`), Babel plugin (`kovar/babel`)
- Source-derived selectors with 0.97 confidence when `data-testid` found in source code
- AST parser with file caching for extracting component metadata (testId, ariaLabel, event handlers)
- `--source` CLI flag for source directory specification
- Page transition grouping by URL in LLM prompt (including hash-based routing for Vue/Angular SPAs)
- LocatorStrategy with confidence scoring (0.4-0.97), fallbacks, and concerns
- Dynamic content detection (strips numeric prefixes like "51 Needs Review" -> "Needs Review")
- `.first()` / `.nth()` fallbacks for non-unique elements
- ARIA context capture (aria-describedby, aria-expanded, aria-selected, disabled)
- Anti-patterns in LLM prompt (bans .or() chains, redundant assertions, hardcoded URLs)
- Few-shot POM example in system prompt
- Request deduplication in LLM prompt (collapses identical API calls with xN count)
- Smart network noise filtering (drops Cloudflare, analytics, tracking, static assets)
- URL post-processing (replaces hardcoded URLs with process.env.BASE_URL in generated code)
- Anti-bot detection bypass (navigator.webdriver override, Chrome user agent)

#### Self-Healing Loop
- `--heal` CLI flag to run generated tests and auto-fix failures via AI
- `--heal-attempts <n>` CLI flag for max self-healing attempts (default: 3)

#### XSS Payloads & Audit Extensibility
- 30 new XSS polyglot payloads across standard and thorough depth levels (40 total, up from 10)
  - Standard (15): encoding evasion, mixed case, null bytes, newline handlers, comment breakouts, quote-style variations, SVG animate, marquee, object/meta/video vectors
  - Thorough (15): unicode escapes, HTML/hex entity encoding, data URIs, base64, context breakouts (textarea, title, style, noscript), polyglot all-context payload
- Extensible audit system via `registerAuditCheck()` -- custom checks can register without modifying `audit()`
- `checks` option in `AuditOptions` for explicit check selection (e.g., `audit({ checks: ["headers", "cookies"] })`)
- `CheckFacade` exported from main entry for external use
- `isReflectedUnescaped()` exported from `@orlalabs/kovar/core` for standalone XSS detection logic
- Unit tests for `isReflectedUnescaped()` -- 13 test cases covering the full truth table
- Comprehensive README rewrite: security module guide, recorder guide, practical examples, CLI reference, confidence level tables

### Changed
- `validateSpecCode()` now requires `expect` in generated specs -- assertion-free tests are rejected
- `extractAndReplaceURLs()` now runs on page object code too, not just specs -- no hardcoded origins in `navigate()` methods
- `sanitizeTestName()` preserves dots and underscores (e.g., `my_test.flow` stays `my_test.flow` instead of `mytestflow`)
- API error handling in Anthropic/OpenAI providers now extracts structured error type/message only -- raw response bodies no longer leak into thrown errors

### Security
- PII masking: credit card numbers ([CARD]) and JWT tokens ([TOKEN]) in form values
- Expanded sensitive header masking (9 named headers + pattern matching for token/secret/key/auth/session)
- POST body sanitization (same filters as response body)
- Response body sanitization (JWT, email, sensitive JSON keys redacted)
- URL sanitization (query params stripped at capture time via safeUrl())
- Hardcoded credential detection in generated code (password, token, apiKey patterns + .fill() with long strings)
- Dangerous code pattern detection (13 patterns: eval, require, fs.promises, readFile, writeFile, import(), Function(), etc.)

### Fixed
- Hardcoded URLs could survive in page object `navigate()` methods when LLM ignored the system prompt
- Inline arrow handler detection (onClick={() => submit()} now extracted)
- Column matching precision (col=0 no longer wildcards to first element on line)
- `.js` endpoint filter (keeps /api/*.js, only drops .min.js/.bundle.js/chunk-*.js)
- isRelevantRequest() checks API/GraphQL URLs before noise patterns
- All cognitive complexity warnings resolved (functions refactored into helpers)
